Defining Routes

In Next.js, you define routes using the file-system based router. This means that the folder structure in your app directory directly maps to the routes in your application.

Creating Routes

To create a new route, you can create a new folder in the app directory. For example, to create a route for /blog, you would create a folder called blog in the app directory. 


app/
├── blog/
│   └── page.tsx
└── page.tsx

In this example, app/page.tsx corresponds to the / route, and app/blog/page.tsx corresponds to the /blog route.

Special Files

Next.js provides several special files that are used to create UI for a specific route segment:

  • page.tsx: Creates a UI that is unique to a route and makes the path publicly accessible.
  • layout.tsx: Creates shared UI for a segment and its children.
  • loading.tsx: Creates loading UI for a segment and its children.
  • error.tsx: Creates error UI for a segment and its children.
  • not-found.tsx: Creates UI for when a route is not found.

Example


// app/blog/page.tsx
export default function BlogPage() {
  return <h1>Blog</h1>;
}

// app/blog/[slug]/page.tsx
export default function BlogPost({ params }: { params: { slug: string } }) {
  return <h1>Blog Post: {params.slug}</h1>;
}

In this example, we've created a blog page at /blog and a dynamic route for blog posts at /blog/[slug].
